# 额度计量表 · 行为说明

composer 输入框右侧的小控件。它只回答一个问题：**你当前所在的那个余额，用了多少。**

下面的示意图是**示意**，不是像素级还原——面板宽度约 320px，中日韩字符在等宽字体里占两格。

## 一、触发按钮

三种状态，一眼可分：

| 你在哪条路线 | 外观 | 悬停 popover |
| --- | --- | --- |
| **Go** | 实心圆环 + 百分比　`◔ 28%` | `5 小时已用 28%` |
| **Zen**（本会话有记录） | 空心圆环 + 消费额　`○ $0.00` | `当前会话消耗 $0.00 · 按量计费` |
| **Zen**（本会话暂无记录） | 空心圆环，不显示数字　`○` | `按量计费 · 无额度窗口` |

**Zen 上不出现 Go 的任何数字。** 没有百分比、圆环不填充、Go 套餐被限流也不会把 Zen 按钮染红。Go 的窗口是 Go 的事；Zen 按 token 计费，它没有会耗尽的东西，所以环是空心的。

│ ──────────────────────────────────────────── │
│ ● 每周       3天3小时后重置              28% │
│ ──────────────────────────────────────────── │
│ ● 每月   11月7日8点55分重置              14% │
│ ──────────────────────────────────────────── │
│                                              │
│ 月度额度                                     │

`ⓘ` 悬停才展开那条计费规则（本会话消耗按轮次归属 / 溢出由网关计入 Zen / 官方不提供「额度内 vs 溢出」拆分）。它是一段**机制说明**，所以藏在悬停后面；而"去控制台开启使用余额"是一条**要动手的指令**，它直接显示。

## 三、Zen 面板

```
┌──────────────────────────────────────────────┐
│ OpenCode Zen                      按量计费   │
│                                              │
│ 当前会话消耗                                 │
│ muse-spark-1.3-contributor · 免费     $0.00  │
│                                              │
│ 更新于 05:00 ⟳                       充值    │
└──────────────────────────────────────────────┘
```

**消费行始终在。** 没有记录时它不消失，而是明说：

```
│ 当前会话消耗                                 │
│ 本会话暂无记录                             — │
```

这一行以前会整行不画——那读起来像"功能没了"，而不像"还没有轮次"。它现在区分得开。

## 四、每一行在说什么

| 行 | 回答的问题 | 只在哪出现 |
| --- | --- | --- |
| 三个窗口 | Go 套餐的 5 小时 / 每周 / 每月额度用了几成，什么时候重置 | Go |
| 月度额度 | 当前模型每月的美元额度是多少（Go / Plus 两档都给） | Go |
| 当前会话消耗 | **本面板所属余额**花了多少 | 两者都有 |
| 可用 Zen 余额 | Go 额度用尽后，请求会被记到哪个余额 | Go |

面板里没有一行是重复的：`按量计费` 只出现一次（徽章），余额行只在 Go 面板（那里它回答了一个真问题）。

## 五、数字从哪来

| 数字 | 来源 | 精度 |
| --- | --- | --- |
| 三个窗口的百分比 | 官方 `/usage` | 精确 |
| 月度额度总额 | 官方 Go 文档表（`pnpm run limits:shim` 生成，CI 定时校验） | 精确 |
| 会话消费额 | 本机按 models.dev 单价 × token 数累加 | 精确到该轮 |

**三种"没有数字"的情况，它们不一样：**

1. **本会话暂无记录** — 累加器是 Host 进程内存里的，**重启 `dsh web` 会清空**；而且它只统计走 OpenCode 路由的轮次。发一轮就有了。
2. **读不到配额** — 凭据缺失或请求失败。此时面板**不画**那三个窗口，而不是画三个 `0%`：编造的零比空白更糟。
3. **额度用尽** — Go 窗口到 100%，面板转为显示 Zen 承接状态。

## 六、设置页上的用量摘要

**设置 → 插件 → OpenCode Patch** 卡片顶部还有一份同一读数的摘要。它和 popover 是**两种风格**：popover 是浮层，这里是设置页自己的平面行（细分割线，不是卡片）。

```
Go 用量                              状态正常
● 5 小时   0% 已用 · 4小时58分钟后重置     100% 剩余
● 每周    28% 已用 · 3天2小时后重置        72% 剩余
● 每月    14% 已用 · 11月7日8点55分重置     86% 剩余
月度额度  mimo-v2.6-pro · Go $60 · Plus $120
OpenCode 每个窗口只提供百分比、没有余额接口，所以「剩余」是同一百分比的反面，而不是美元数；套餐档位也无法探测。
```

**「剩余」是百分比，不是美元。** 官方 `/usage` 每个窗口只给一个百分比、没有余额接口，而套餐档位（Go $60 / Plus $120）无法探测——所以任何"剩余多少钱"的数字都会是猜的。上面那行说明就是为了让这一点写在界面上，而不是靠读者推断。

读不到配额时它写「读不到配额」，**不画任何数字**：这个页面没有重试入口，一排 `0%` 会被当成真实读数。

## 六、截图

真图由脚本生成，落盘到本目录：

```sh
scripts/capture-ui.sh "<带 ?token=... 的 dsh url>"
```

token 由 `dsh web` 运行时生成、不落盘，所以要手动传入。产物是 `docs/composer-dock.png`（触发按钮）和 `docs/meter-panel.png`（面板）。

## 七、两条设计规则

- **一个数字说不出真话，就不渲染它；由解释"为什么没有"的说明来补位。** 估算穿着精确的外衣，比一句说明更糟——它读起来像测量值。
- **解释可以藏在悬停后面；指令不行。**

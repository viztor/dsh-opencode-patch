# The quota meter · what it does

The small control at the right of the composer. It answers exactly one question: **how much of the balance you are actually on has been used.**

The diagrams below are sketches, not pixel renderings — the panel is about 320px wide, and CJK glyphs take two cells in a monospaced font.

## 1. The trigger

Three states, distinguishable at a glance:

| Which route you are on | Appearance | Hover popover |
| --- | --- | --- |
| **Go** | a filled ring plus a percentage — `◔ 28%` | `5-hour 11% · Weekly 33% · Monthly 16%` |
| **Zen**, with a record this session | **no ring**, just the spend — `$0.00` | `Session spend $0.00 · Pay-as-you-go` |
| **Zen**, no record yet | no ring and no number — `—` | `Pay-as-you-go · no quota window` |

**No Go figure ever appears on a Zen route.** No percentage, the ring stays hollow, and a rate-limited Go plan does not tint the Zen trigger red. Go's windows are Go's business; Zen bills per token, **has no quota to measure, and therefore draws no ring at all** — a permanently hollow ring says nothing.

### Which window the ring answers for

**Not the highest percentage** — the one that can answer the question:

1. A window that is **already out** takes precedence, widest first: monthly → weekly → 5-hour. A monthly cap explains a refusal; the 5-hour window cannot.
2. When none is out, the **5-hour** window is shown: it resets soonest, so it is the one you can still act on.

(The ring used to take the highest percentage, so 5-hour 11%, weekly 33%, monthly 16% showed _weekly_ — while the window actually constraining you was the 5-hour one.)

Hovering lists **all three**, because the trigger can print one number and the next question is always "what about the other two?".

**The spend row is always drawn.** With no record it does not disappear — it says so:

```
│ Session spend                                │
│ No turns yet in this session              —  │
```

That row used to be omitted entirely, which reads as "the feature is gone" rather than "there have been no turns yet". It now tells the two apart.

## 4. What each row is for

| Row | The question it answers | Where |
| --- | --- | --- |
| The three windows | how much of the Go plan's 5-hour / weekly / monthly allowance is used, and when each resets | Go |
| Monthly allowance | what this model's monthly dollar allowance is, both tiers | Go |
| Session spend | what **this panel's own balance** has cost | both |
| Available Zen balance | which balance an over-limit request is billed to | Go |

No row repeats another: `Pay-as-you-go` appears once, in the badge, and the balance row lives only on the Go panel, where it answers a real question.

## 5. Where the numbers come from

| Number | Source | Precision |
| --- | --- | --- |
| The three window percentages | the official `/usage` endpoint | exact |
| The monthly allowance totals | OpenCode's own Go documentation table (generated by `pnpm run limits:shim`, checked on a schedule in CI) | exact |
| Session spend | accumulated locally from models.dev rates × tokens | exact per turn |

**Three different "no number" states, and they are not the same thing:**

1. **No turns yet in this session** — the accumulator lives in the Host process's memory, so **restarting `dsh web` clears it**; it also counts only turns that ran on an OpenCode route. One turn fills it.
2. **Quota unreadable** — a missing credential, or the request failed. The panel then draws **no** windows rather than three `0%` rows: a fabricated zero is worse than a blank.
3. **Allowance exhausted** — a Go window is at 100%, and the panel switches to showing the Zen takeover state.

## 6. The usage summary on the settings page

The **Settings → Plugins → OpenCode Patch** card carries a summary of the same reading at the top. It is a **different surface** from the popover: the popover floats, while this is a flat row of the settings page itself (a hairline divider, not a card).

```
Go usage                            Healthy
● 5-hour   0% used · resets in 4h 58m      100% left
● Weekly  28% used · resets in 3d 2h        72% left
● Monthly 14% used · resets Nov 7, 8:55 AM  86% left
Monthly allowance  mimo-v2.6-pro · Go $60 · Plus $120
OpenCode publishes only a percentage per window and no balance endpoint, so "left" is the inverse of the same percentage rather than a dollar figure; the plan tier cannot be probed either.
```

"Left" is a percentage, not money. The official `/usage` gives one percentage per window and no balance endpoint, and the plan tier (Go $60 / Plus $120) cannot be probed — so any "how many dollars are left" figure would be a guess. That line of explanation is on the surface so the reader does not have to infer it.

When the quota cannot be read it says so and **draws no numbers at all**: this page has no retry affordance, so a row of `0%` would be taken for a real reading.

## 7. Screenshots

The real images are produced by a script into this directory:

```sh
scripts/capture-ui.sh "<dsh url with ?token=...>"
```

The token is generated at runtime by `dsh web` and never written to disk, so it has to be passed in. The output is `docs/composer-dock.png` (the trigger) and `docs/meter-panel.png` (the panel).

## 8. Two design rules

- **A number that cannot tell the truth is not rendered; the explanation of why it is absent takes its place.** An estimate wearing a precise outfit is worse than a sentence — it reads as a measurement.
- **An explanation can hide behind a hover; an instruction cannot.**
